1One trigger, two tabs. The View button opens a 320 px popover rather than a menu: segments and toggles show every value at once, where radio rows spent a line each. It names a source that is not Output — View Next GO — because that is the one setting that makes the picture not the output.
2View is what this window sees; Performance is what it costs. The split is by purpose. Scope is written on every group — this window or this machine — rather than implied by the tab.
3Source as a 2 × 2. Only the chosen source's hint is shown, and Next GO's live status under it. The hint stays: Output + Programmer reads as broken without it.
4Show is seven toggles in two rows: the rig's four, then the scene's three. They move from one value per browser to per window, so the hall screen can drop the rigging without the desk losing it. Beam cones becomes Light: since light lands through the surface shader, off draws no beam and no pool (Model board).
5Work lights: Off | On. The stage-light plan's Readable, named for what it imitates. New, per window, and announced beside the source so a Screens row can set it. See the Work lights board.
6Performance leads with what the canvas is doing — frame rate, the lights the budget packs, the haze tier — so the three machine settings are chosen against a number. Test recovery moves here.
7The readout, off by default, bottom-left: frames per second and ms a frame while frames are drawn, idle otherwise. Click opens Performance. See the Readout board.
