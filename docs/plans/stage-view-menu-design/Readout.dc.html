The frame-rate readout

The canvas draws on demand, so a frame rate only means something while frames are being drawn. The readout says what the canvas is doing now: frames per second and ms a frame while it draws, idle when it has drawn nothing for a second. Off by default, per window, toggled from Performance. The numbers below are illustrative; the pane this board was drawn from throttles requestAnimationFrame, so no honest rate could be read there.

Drawing. An orbit, a fade, a spinning gobo. Frames counted over the trailing second; ms is the median gap between frames less than a second apart.

Slow. Amber past 28 ms a frame — the haze governor's own step-down line — so when the beams turn grainy the operator can see why.

Idle. Nothing drawn for a second: the stage is still. A timer flips it, not a frame, and a hidden tab reads idle when it is shown again.

Rules

It never asks for a frame. A readout that invalidated would keep a demand canvas drawing forever and measure itself. It is fed from the frame loop it measures (beside HazeGovernorProbe, priority 2) and writes its text straight to its DOM node at most four times a second; the idle flip is a setTimeout. A test mounts it in a demand canvas and asserts no frame is requested.

It counts what is drawn, not what it costs. ms a frame is the interval: a light scene on a 60 Hz display reads 16.7 however little the GPU did. A GPU timer is not portable (Safari has none), and the per-pixel cost of a setting stays the occlusion bench's job.

Per window, in sessionStorage, not announced (stage.frameRate). Each window draws its own canvas at its own rate; as a machine setting it would switch on over the hall screen too. Never in a render_view capture — it is DOM over the canvas, and the job does not mount it. Clicking it opens the View popover on Performance.

The live block reads stores, not the DOM. Today the light counts are stamped as data-lights and the haze tier as data-haze-tier for measurement; the Performance tab reads the same values from a small stats store those writers also feed, and the attributes stay.
