Edit the cue where you read it

The Show view shows a cue and can't change it: every edit is a trip through the programmer, and that trip puts the cue on stage unless Blind is on first. This plan puts the programmer's own tables (values, Looks and effects) inside the cue card and under the cue table. They write the stored cue and never send output. One action set does the rest, in both views.

The engineering plan is docs/plans/show-cue-editing-plan.md; this page is its one-page copy, checked in as docs/plans/show-cue-editing-design/show-cue-editing.html. Where they differ, the markdown wins. It designs against the cue model of R1 (cue-model-plan.md): a cue is shared, a stack is a list of entries, and delete is its own act.

The problem§1

On the first evening in the hall, a cue was read in the Show view and changed somewhere else. The card says what the cue holds and offers Edit in Programmer, which Includes it and so lights it. The table view has no edit, no Record, no duplicate and no delete at all. What the code says, read from main at a6e4053:

A stored edit never reaches the stageA cue PATCH fires list frames and nothing else. Only Record, Update and a Look or palette contents edit republish a live cue. So a table that writes the cue is silent by construction, and a live cue it edits goes stale.routes/projectCues.kt:190, 280 · programmerRecord.kt:581
Blind does not hold effectsBlind takes the programmer's values and layers out of the merge, but effects the programmer runs keep painting. Include spawns a cue's effects, so "Edit in Blind" today still puts them on the rig.fx/FxEngine.kt:207 · lighting-composition-model.md §Blind
The read surface is long, and its verbs are lastQ1 in Sleeping Beauty expands to values, five layers and more than a dozen tracked scenery rows before Remove · Duplicate · Edit in Programmer · Record, a screen and a half below the cue's name.CueCardEditor.tsx:417 · CueDetailContent.tsx
The programmer already has the tablesThe value grid scopes its writes (Output, Local, a focused Look's rows), the Look stack and FX fields are host-agnostic. A cue scope is a fourth writer, beside the Look layer's.ProgrammerScope.tsx · useCellWriters.ts:124 · FxEffectFields.tsx:110
A cue write replaces its childrenEvery PATCH deletes and recreates the rows, layers and effects, so each child gets a fresh uuid. An editor that saves per gesture would rewrite the whole cue in sync, the problem PR #140 fixed for Looks.projectCuesHelpers.kt:519, 630
Cue properties is a second editorName, number, fade, follow, notes, scenery, events, hooks and busk pages sit in a drawer, opened from the card or from the FX tray's on Q12. The cue's values are edited nowhere but the programmer.CuePropertiesSheet.tsx · CuePropsPane.tsx

Where an edit goes§3.2

Decisions§2

Agreed with Chris on 2026-10-14 in three rounds, on top of R1's D1–D18. Where this plan and R1 disagree inside this plan's scope (cue editing and the action set), this plan wins.

#Decision
D1One cue editor, two hosts. The expanded card's body and the table view's bottom pane mount the same editor: a header (number, name, fade, curve, follow, the shared chip, the save state) and tabs Values · Looks · FX · Scenery · Events · Cue.
D2The Values grid shows what GO lands and edits the cue's own rows. Each cell says whether it is own or which Look won it. A typed value becomes an own row, which wins over every layer, so you see what you typed. ⌫ removes the own row and shows the layer underneath again.
D3A Look layer is edited as a layer, never as a Look. Add, remove, reorder, enable, amount, mask, blend, stomp and targets are stored on the cue. Open Look goes to the Looks library, because a Look edit changes every cue that layers it and republishes the live ones.
D4A live cue edited in place is marked, and Update stage is the one way to send it. Edited since GO on the card, the row and the pane; the next GO into it lands the edit. Update stage is explicit and confirmed.
D5The table view's editor is a bottom pane under the cue sheet, for the one selected row, with a drag handle for its height. No row or several rows: no pane.
D6Edit in programmer is a split button whose default follows the show. Stopped: Edit in programmer, with Blind edit in its menu. Running: Blind edit in programmer, with the live edit in its menu.
D7Blind holds programmer effects too. Effects the programmer runs are staged while Blind is on and start when it goes off, as values do.
D8Locked, the tables read and Blind edit still works. Both views draw the whole action set; every action but Blind edit asks to unlock, as the cue sheet's verbs do today.
D9The phone card gets the action set in a ⋯ menu, and its body stays a read-out. A values grid is not a phone surface.
D10Edits save as they go, coalesced (400 ms, 2 s ceiling, whole list rebuilt at flush), with the cue's save state in the header and an Undo toast for the last edit.
D11Update stage sends rows and effects at the cue's fade. Rows republish over the cue's own fade; effects are brought in line (a changed one edited in place, phase kept; a removed one stopped; a new one started). Events and scenery are not re-fired.
D12Duplicate appends the copy to the end of the stack (venue-visit S3's rule), and opens it. This replaces R1 §3.8's "after the source's entry".
D13The Stage view can draw the cue in edit. A vis source, Cue in edit, composed by the preview route and drawn, never output; the editor's Show on stage points this window's Stage at it.
D14The grid lists the cue's fixtures: every target of an own row or a layer, in rig order. + Fixtures… adds rows, and Whole rig lists every fixture.
D15Cue properties folds into the editor. The drawer retires; the FX tray's on Q12 and the Stage's Moves with open the editor instead.
D16The programmer's source box gains ← Show while the include came from the Show view: back to that stack with the cue open.
D17An effect is added through the FX picker, in draft. A tap adds it to the cue with its defaults and runs nothing; its fields are the live editor's, over the stored effect, plus the cue's timing.

The plan's own: P1 one PR per session; P2 nothing in the Show view sends output but Update stage, and every surface that would (the desk selection, Locate, Highlight, Release, the palette strip) is left out of the cue grid; P3 a cue's children keep their uuids across a write; P4 the editor writes the cue, so a shared cue changes in every stack and the header says so; P5 the entry's fields (number, follow) are this stack's, and the header says which.

The editor§3.3, §4.1

One component, CueEditor, with the programmer's pieces inside it. It writes through a cue row store shaped like the focused Look layer's, so the grid's gestures (marquee, Enter, typing, Set · Clear · Spread, the three editor forms) are the programmer's own.

Values

  • Rows: the cue's fixtures and groups, a multi-head's cells under it; + Fixtures…, Whole rig.
  • Cells read /cues/{id}/cooked: the value GO lands, edged own or by its Look.
  • An edit writes an own row; Spread asks the desk with write:false and lands the literals.
  • ⌫ removes own rows; a Look-won cell has nothing to clear.
  • No desk selection, Locate, Highlight, Release or palette strip (P2).

Looks

  • The programmer's LookStack, top wins, over the cue's layers.
  • Enable, amount, blend, mask, stomp, drag to reorder, × to remove, targets from the Values selection.
  • + Look and + Palette pickers; the hand places here as today.
  • Open Look leaves for the Looks library (D3).

FX

  • One row per stored effect: target, effect, property, speed and master, timing.
  • A row opens FxEffectFields over the stored effect, with delay · interval · random under it.
  • + Effect: the picker over the Values selection, in draft (D17).
  • A Look's effects are listed under the Look, read-only.

Scenery · Events · Cue

  • Scenery: CueSceneryEditor, the cue's rows and what it tracks.
  • Events: CueEventsEditor.
  • Cue: notes, script hooks, busk pages, what was in Cue properties.
  • The header: number and follow (this stack's entry), name, fade, curve, in 2 stacks.

A live cue, edited§3.5

Because a stored edit is silent, an edited live cue no longer matches the stage. The desk says so: R1's hold registry marks a held cue edited since GO when its rows, layers or effects change, and cueHolds.state carries the mark. Scenery is drawn and already follows its edit; events fire only on GO.

Sessions§6

One PR each, in this order. Sessions 1 and 2 need nothing from R1 and can land at once; session 3 onwards needs R1's sessions 1–4 and venue-visit S3.

  1. Blind holds programmer effectsbackend + reporters

    Programmer-band effects are staged under Blind and start when it goes off, at the Blind fade; the busk pill, the Show tab dot and the indicator say "values and effects held".

  2. A cue's children keep their uuidsbackend

    writeCueChildren reconciles rows, layers, effects and hooks by natural key, as Looks have since PR #140, so a per-gesture save changes one record in sync and Update stage can match effects.

  3. The action setfrontend + duplicate route

    CueActions on the card, the sheet's bar and the phone ⋯; the split Edit and Blind edit; Load; Record; Duplicate (POST /cues/{id}/duplicate, appended); Remove from stack; Delete…; the locked rule; ← Show in the source box.

    needs session 1, R1 sessions 1–4, venue-visit S3
  4. The cue editor and its two hostsfrontend

    CueEditor's header and tabs in the card body and the table's bottom pane; Scenery, Events and Cue tabs from the existing editors; Cue properties retired; Values, Looks and FX as today's read-outs.

    needs session 3
  5. The Values gridfrontend + cooked route

    The cue row store, the writers' cue arm with no live fallback, composed reads with source edges, the rows rule, Spread with write:false, ⌫, Undo; /cooked keeps a group row's key.

    needs sessions 2, 4
  6. The Looks and FX tablesfrontend

    The cue host for LookStack (whole-list PATCH, sortOrder restated), the Look and palette pickers, Open Look; the FX table over FxEffectFields with the cue's timing and the picker in draft.

    needs session 5
  7. Edited since GO and Update stagebackend + frontend

    The mark on R1's holds and cueHolds.state; POST /cues/{id}/update-stage at the cue's fade with effects reconciled by uuid; the band, the chip and the confirm.

    needs sessions 2, 6, R1 session 2
  8. Show on stagefrontend + preview route

    The Cue in edit vis source on the Stage view and Positions, an entry's preview route, the editor's toggle, and the source on the Screens sheet.

    needs session 4

Out of scope§8

  • Pressing a palette onto cue cells. How a palette, a Look or an effect reaches a selection is R3's.
  • Editing a Look's contents from a cue. D3; the Looks library does it.
  • A row's own fade and move-in-dark. Kept on every write and shown on the cell's hover; editing them is a follow-up.
  • Values tables on a phone (D9).
  • Drawing a cue's effects in the Cue in edit source. The preview route composes Layer 4 only.
