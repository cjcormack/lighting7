Stack pads

A busk pad that steps through a cue stack of its own: a musical number's verse, chorus and bridge on one pad or one surface button, GO by GO, or a short stack that runs itself when Carabossy enters and hands the stage back when it ends. Settings on that stack keep it out of the show's running order and say whether it adds to the main stack's look or replaces it.

1What the desk does today

A pad holds a palette, a Look or a cue

busk_pads has three nullable references and a CHECK that exactly one is set. A cue pad takes or lets go of a loose hold on one cue, above every stack. It never steps anything: there is no pad that names a stack.

A surface can already GO any stack

The CueStackGo(stackId) binding calls CueStackManager.go: start the stack on its armed or first cue, else advance it. Each stack has its own run state, so a GO on one moves no other. A stack can't be stopped from a button: there are Go, Back and Pause bindings and no Release.

Every stack is in the running order

The show is the project's ordered list of stacks, and its playhead (projects.active_stack_id) walks every STACK row. The Show view's GO with nothing on deck calls /show/advance, which releases the stack it leaves and starts the next one. A song stack placed after Act 1 is where Act 1's last GO goes, and the stack the operator was running from a button is restarted from its first cue.

2Busk stacks stay out of the running order

Now

The only way to keep a song stack away from the show's GO is to put it first or last in the list and never step past it. The stack's own settings are its name, Loop and Move in dark.

components/cues/CueStackForm.tsx · models/cueStacks.kt:21
Change

In the running order, a switch in the stack's settings, on for every stack that exists and every new one. Off, the stack is a busk stack. Beside it, After the last cue: Stay, Loop or Release, the last new. A busk stack defaults to Release once the switch is turned off (Q3).

cue_stacks.in_running_order · cue_stacks.release_at_end

Rules

  • The running order is the stacks in it. orderedStacks() filters on the setting, so the playhead's activate, advance and BACK skip busk stacks, and /show/go-to on one is 409 CUE_STACK_NOT_IN_SHOW. The client's boundary GO and the next-stack label beside it read the same list. The playhead stack cannot be switched out of the running order while it is the playhead (409 CUE_STACK_IS_PLAYHEAD), and a show stack that released at its end has nothing on deck, so the show's GO moves on to the next stack.
  • A busk stack runs exactly as any stack runs, through CueStackManager: its GO sets the cue's tempo, follows, Move in dark, scenery, events, the stack's FX amount. Nothing in the run path reads the new switch but the priority band (§3).
  • How it sits over the show's stacks is §3: above the running order, adding or replacing.
  • Release at the end is a GO past the last cue entry, or a follow off the last one, releasing the stack over its release time (§3). Loop and Release are one choice, so the request refuses both on. A short stack whose cues all follow therefore runs itself from one press to its hand back.

3Over the main stack

The main stack holds the base look; a busk stack runs on top of it. Two uses want different things from "on top". A song's stack adds: a chase and a colour change over the base, the base still lighting what the song leaves alone. Carabossy's stack replaces: the warm kitchen goes, green and lightning take the stage for a few seconds, and the kitchen comes back when the stack ends. Today neither is dependable.

Intensity only goes up

Dimmer, UV and strobe are highest-takes-precedence across every live cue. A busk cue that sets the front wash to 0 while the main stack holds it at 80 % leaves it at 80 %. A stack can add light; it cannot take any away.

fx/CueAssignmentResolver.kt:367, :501 · composition model §"Composition rules by AttributeCategory"
The rest goes to whichever stack was made later

Colour, position and beam are LTP by priority, and a stack hold's priority is stackId × 1 000 000 + position × 1 000 + 1. A song stack made before Act 1's stack loses every colour to it, whichever started last. Only a loose press ranks by recency (LOOSE_BAND + seq).

fx/CueApply.kt:233 · fx/CueHolds.kt:933
The main stack's FX keep running

FX are Tier 3, above every cue's values. A dimmer chase in the main stack's cue still paints over a busk cue's dimmer 0. Cue stomp removes other cues' FX for good, so they would not come back when Carabossy leaves.

A release snaps

deactivateStack lets the hold go with Departure.SNAP: the busk cue's values drop out in one frame and the main stack's look jumps back.

fx/CueStackManager.kt:472

The change

  • The latest GO wins, and busk stacks rank above the running order. An operator's cue change on a stack (a start, a GO, a GO TO, a BACK, a pad press) makes it the newest in its band, as a loose press is today; a follow does not, so a looping chase never climbs back over your latest GO. There are two bands: the show's stacks, and above them the busk stacks, so a GO on Act 1 never overtakes Carabossy. Loose presses and the programmer stay above both. Creation order stops mattering everywhere (a stack's place in the show's list never mattered): whatever you triggered last wins its LTP attributes. Inside a stack, entry position still ranks the two cues of a crossfade.
  • Over the show: Adds or Replaces, a busk stack's setting. Adds is today's rules inside the new band: intensity still folds by highest, so the song's chase lifts heads over the base and never darkens them. Replaces makes the stack's live cue the floor of every attribute it sets, intensity included: what is below it on that attribute no longer shows, so a head it sets to 0 goes to 0, and a head it does not name keeps the main stack's state. Its start snaps on, as every stack's start does; its GOs crossfade within it, and its release fades back to the value the stacks below compose to, with no jump. Anything above it, a cue pad pressed during Carabossy's entrance or a song stack GO'd after her, still composes over her by the attribute's usual rule.
  • Replaces holds back the FX underneath. On a key a replacing cue sets, every FX at a lower priority but the programmer's, a main-stack cue's and a manual or script FX included, is held back rather than removed, by the replacing cue's fade: fully once it is in, handing back as it fades out. FxSuppression gains a fourth reason, REPLACED, beside stomp, the programmer and Blind. The chase keeps its phase throughout and grows back over the release. The busk stack's own FX run, and so do the programmer's.
  • A release fades over the stack's Release time (default 2 s, 0 snaps), on every stack, whenever someone stops it: Release at the end, the pad's menu, the Show view's stop, Claude's deactivate_cue_stack, a solo bank releasing a sibling, the CueStackStop binding or OSC's /stop. The stack reads stopped at once; only its light fades. A stack delete, an undo, a project switch and the show's own advance and go-to still let go at once of a stack that is running; a release already under way is left to finish. The outgoing cue's rows and FX shrink by fade weight, so a replacing stack hands every key back to the main stack's value across the release.
  • The main stack keeps running underneath. A GO on Act 1 while Carabossy holds the stage lands under her: visible at once on keys her cue leaves alone, and on the rest when she releases.
  • The programmer is still on top, Tier 2 over both stacks.

4The stack pad

Now

A cue pad shows a number, a name and the stacks that place it; it is lit solid while held loose and outlined while only a stack holds it. A press is the loose hold's toggle. A song of five cues needs five pads, and pressing them out of order is easy at speed.

components/busking/BuskPad.tsx · padFace.ts
Change

A pad that names a busk stack. Tap is GO: stopped, it starts the stack on its armed or first cue; running, it advances. Its face is the stack's run state: the name, the live cue's number and name, the next cue, and the fade. Its hold menu: GO, Back, Release and View, which opens the stack on the Show view.

5Solo banks

Solo has one meaning for every kind: pressing a pad on turns its siblings off (busk-layout plan D6). A stack pad keeps that meaning, with "on" read as the stack starting.

PressWhat it takes off in a solo bank
A stack pad that starts its stackWhat a cue pad's on press takes off: layer siblings (palettes and Looks) off whole through ProgrammerLayerStack.release, cue siblings' loose holds let go, and every sibling stack pad's stack released.
A stack pad that advances its stackNothing. The stack is already on; a GO is a step inside it.
A palette, Look or cue pad pressed onAs today, plus every running sibling stack is released.
Release, from the menu or a bindingNothing: an off press releases nothing.

So a solo bank of three song stacks is a selector: starting one releases the others. In a stacking bank (solo off) the stack sits beside Looks it does not touch, which is how the mock-up's Sisters spot stays on through the chorus.

6Surfaces and OSC

Now

PressPad(padUuid) runs the busk press service, so a bound button presses exactly as the screen does. Its LED is the pad's ring, read per kind in SurfaceFeedbackPublisher. Stacks have CueStackGo, CueStackBack and CueStackPause. The OSC plan, on main and not yet built, adds CueStackStop, a SurfaceDispatch both doors share, and addresses under /lighting7/.

midi/BindingTarget.kt:354 · SurfaceFeedbackPublisher.kt:888, :1033 · docs/plans/osc-plan.md §3
Change

A PressPad on a stack pad needs nothing new on the input side; its LED is lit while the stack runs, read from the stack's run state. Stopping a stack from a button is the OSC plan's CueStackStop, not a binding of this plan's, and it fades over the stack's release time like every deliberate stop. This plan's pad and surfaces sessions wait for OSC session 1 to merge (Q12).

SurfaceFeedbackPublisher.padLed · BuskPressService's outcome through SurfaceDispatch

From QLab

  • A busk stack has OSC addresses with no work here. OSC names stacks by slug and skips only separators, so Carabossy is /lighting7/stack/carabossy/go. /stack/carabossy/cue/1/go is the one to put on QLab's sound cue: fired twice while cue 1 is live, it does nothing.
  • A stack pad is a predictable pad. /busk/{page}/{bank}/{pad}/press presses it, and it names no fixtures, so the desk's selection does not change what it does. It joins the Look and cue pads the OSC plan calls predictable from QLab.
  • The running order is the playhead's, not OSC's. OSC's stack addresses call the stack, never the show's playhead, so taking a stack out of the running order changes nothing for them.

A surface can run a song three ways: a PressPad on the busk pad, which follows the pad if it moves page; CueStackGo on the stack itself; or an OSC address. All three are the same GO.

8Edges

  • Release disarms one-shot effects, as every stack stop does (onStackStopped). A song's release mid-act drops a pyro arm made for the main stack. Kept as the safe default (Q8).
  • The programmer still sits above every stack. Looks busked over the song stay on after it releases; Clear is still the operator's.
  • The show stopped (no playhead): a busk stack still starts, runs and releases. Stopping the show releases the playhead stack only.
  • A project switch drops every stack, busk stacks included; a reload carries each stack's live entry through ShowCarry, as today.
  • An empty busk stack: a tap does nothing and the pad reads no cues, rather than a 400 at the press.
  • Venues: a venue has no cue stacks, so nothing changes there.
  • Out of scope: Clear on GO, an on-screen GO for busk stacks outside the busk view, the hand carrying a stack, and an MCP tool for busk pages.
