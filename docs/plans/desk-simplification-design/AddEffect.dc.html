Adding an effect — the scope decides where it lands

There is no per-layer effect list, and I am not proposing one. CueLayer carries no effects — only overrides. So + Effect follows the same rule as a value edit: it goes wherever the focused scope’s values go.

Focused: a layer

Goes into the Look, as a LookEffect.

It travels with the Look, so every other layer applying it starts running the effect too. Same consequence as editing its values — so the same guard fires:

All 9 layers Duplicate for this cue
Focused: Local values

Goes on the cue, as a CueAdHocEffect.

Local has no Look to put it in, and that is exactly right: an effect you want here only belongs to the cue. This is the “just this once” path — no shared-edit question to answer.

Before the cue exists it is a programmer-band effect, and Record writes it into adHocEffects.

Focused: Output

+ Effect is disabled.

Output is the cook — a read of what every entry produced together. It owns nothing, so there is nowhere for a new effect to go. The button’s tooltip says so and names the two places that can take one.

Same reason the Output scope cannot take a value edit. One rule, consistently applied, rather than a special case for effects.

What a layer can change about an effect it does not own

speedMasterUuid Which tempo bus its beats come from. BEAT only
rateSpeedMasterUuid Scales a wall-clock effect’s cycle. WALL_CLOCK only
amount Mix of the whole layer over what is beneath it.
propertyMask Which families the layer asserts at all.
stomp Suppresses effects below this layer. reversible
enabled Off takes the layer’s effects with it.

These are already on CueLayer today — nothing new to add. The comment on speedMasterUuid spells the fallback out: null → each Look effect’s own → master 1. That is the whole per-use story: one definition, many tempos.
