Surface code review

The agreed model fits the code better than the code fits itself. The desk already resolves a direct binding before a strip, and a strip is already a small job. What makes the code large is that the subject (selection, group, fixture) is baked into the type, and each function's read, LED and jump rule live in separate hand-kept tables. This review proposes a binding with the subject as a field, a function definition that carries everything about one function, and a desk that serves the resolved picture to the browser instead of the browser re-deriving it.

Summary

Four changes carry most of the payoff

1 · The subject becomes a field

One Binding(does, on, how) replaces the Fixture / Group / Selection triplets and the separate on-off targets. The three group fan-outs become one expansion that also reaches elements. Every switch that asks "does this name a fixture, a group or a record" reads binding.on instead.

2 · One definition per function

Each function declares what it accepts, how it writes, how it reads back, its LED and its jump rule. The seven feedback entry kinds, the LED when with else → null, the kind tables and the six jump rules collapse into it. Adding a function touches one class.

3 · Readback from Local, off the ArtNet thread

A fixture control reads what composeProgrammerOver already composes, without its Blind gate, over the cue layer. A feedback loop polls the programmer's epoch, its Blind flag and the cue layer, instead of running on the transmit thread for every channel change.

4 · The desk serves the picture

A resolved map per control part (label, where it writes, health, direct or job) and one function catalogue. The browser stops mirroring the resolver, the kind tables and the label rules, and the inspector, table and assign flow draw one form from the catalogue.

Size

Frontend: about 5,500 lines out (a third of it tests), 2,000 in. Backend: about 450 out of the publisher and about 400 out of dispatch and the model, before the new functions and jobs are added. These are the reviews' estimates.

Cost

A database step and sync formatVersion 53 with minReader 53: an older desk would read every binding as unknown. The OSC addresses don't change. Three behaviours operators will notice are listed under migration.

Target design · 1

The binding

The 50 variants become about 36 functions plus the five new ones (Clear, Blind, Release, Record, Update). The variant count barely drops. The payoff is that the eight places that switch on a variant today (dispatch, health, kind tables, bind-time refusals, uuid fill, rename, delete guard, colour-axis check) read one definition.

@Serializable data class Binding(val does: Does, val on: Subject = Subject.None, val how: How? = null)
// The slot key gains a part: (deviceType, controlId, part, layer). Pick up / Jump stays the takeover column.

sealed interface Subject {
  None; Selection
  Group(key); Fixture(key)               // element keys included
  Slot                                   // a job's template only
  Record(kind: STACK | ENTRY | CUE | LOOK | PALETTE | PAD | BANK | PAGE | MASTER, uuid: UUID)
}
enum class How { TOGGLE, WHILE_HELD, ON, OFF, TOGGLE_HOLD_REPLACES, REPLACE }
data class Spec(writesTo: LOCAL|PLAYBACK|MASTER|TEMPO|DESK, on: Set<SubjectKind>,
                inputs: Set<ControlKind>, hows: Set<How>, defaultHow: How?)

sealed interface Does { val spec: Spec; fun act(on: Subject, op: Op, ctx): Acted }
// Op = Move(v7) | Set(value) | On | Off | Toggle | Replace. How becomes an Op in one dispatch.

@SerialName("clear") object Clear : Does {      // a new function is one declaration
  override val spec = Spec(LOCAL, setOf(NONE), setOf(BUTTON), setOf(ON), ON)
  override fun act(on, op, ctx) = ctx.programmer.clear()
}

Still special, and why

  • Unknown, so a newer archive's binding survives.
  • Placing the hand on a bank, which drops only if the place succeeds.
  • The fan's anchor and FX speed's lead FX: state kept behind act, now taking the subject instead of reading the desk selection.
  • Undo, Record and Update on the serial lane, since they open transactions and reload.
  • Window functions, addressed by name, with health that changes as windows come and go.
  • Switch layer, Encoder page and Undo, which act on the device or source the press came from.
Target design · 2

Feedback

The publisher has seven entry kinds with no shared base, nine LED lists, 17 subscriptions each with its own job, and hand-kept resync lists that have already drifted. In the target, each function also says what it reads and when that read changes.

interface ContinuousFn : Does { fun read(ctx, on): Reading      // Value(v7, tolerance) | Mixed | None
                                fun signals(on): Set<Signal> }   // Programmer, CueLayer, Selection, Tempo(m)…
interface ButtonFn : Does { fun led(ctx, on): Boolean? }          // abstract: a missing LED is a compile error

publisher: invalidate(signal) → dirty entries → feedback loop (≈50 Hz, off the ArtNet thread)
           → fn.read(on) → apply(entry, reading)                  // tracker, takeover, touch gate, send

Local-first readback

  • The value: FxTarget.composeProgrammerOver(fixture, store, below = cue layer), which is LayerResolver.fallbackFor without its if (blind) return below. Expose it once and have fallbackFor call it, so output and readback can't disagree. LayerResolver.kt:324 · FxTarget.kt:200
  • When it changes: poll three cheap facts: the store's epoch (bumped on every put and clear), its Blind flag, and the identity of the cue-layer snapshot. A programmer change in Blind never reaches the wire, so channel deltas can't be the trigger.
  • Cost: one compose per head per change, a few hundred on an X-Touch, off the transmit thread. The per-frame recompute during an FX goes away.
  • The write reads the same base, so a colour move builds on the staged colour in Blind and a ring never shows a position a move wouldn't reproduce.
  • Provenance and the key stack can't be the source: one carries owners, not values, and the other is a cold per-request read.

One jump rule

  • A driven control (motor fader, ring encoder) accepts a move within J of what it shows, or while touched. Otherwise it ignores the move and shows its value again.
  • An undriven fader picks up when it crosses the value.
  • Mixed accepts, as today.
  • Echo: after an accepted move, the shown value stays the physical one while the function reads back to it. That replaces the FX-speed fader rule and the ±1.
  • Replaces soft takeover's crossing, the disarm, the fan's PICKUP_STEPS, FX speed's ENCODER_JUMP and its echo rule, and the unguarded strip encoder. SoftTakeoverStateMachine.kt:120 · SelectionFan.kt:226 · SelectionFxSpeed.kt:191
  • The rig has to confirm the X-Touch adopts a ring value it's sent, which FX speed already assumes.

The new LEDs are cheap: providers already exist for a running stack and a cue held loose, and the store has Blind. An encoder's push LED needs encoders indexed as buttons and the X-Touch's momentary LED re-asserted on release, as buttons are now. SurfaceFeedbackPublisher.kt:1014, 703

Target design · 3

Jobs

  • The profile declares job regions with ordered slots and roles, generalising strip(). These are kept apart from the picture's layout regions: the picture must place every control, while a job region needs slots. On the X-Touch, the layout's strips region holds three button rows no strip claims, and right mixes encoders with transport keys.
  • A job is its own stored record, keyed by device type, layer and region. That frees the control_id column of strip ids.
  • Resolution keeps today's order exactly: a direct binding at the exact layer, a direct binding on both layers, then the job at the exact layer, then on both. ControlSurfaceBindingService.kt:188–233
  • deriveStripTarget becomes job.bindingFor(slot, role) over a template whose subject is Slot.
  • A job that follows live state (the selection's heads, the busk page that's showing, the encoder page) re-derives only its region when that state moves, and doesn't re-arm pickup.
  • Today every selection change rebuilds the whole index and resyncs every device. With the selection as a signal, that becomes a region-level re-derive. SurfaceFeedbackPublisher.kt:455

Frontend

Three copies of backend rules live in the browser today, and their failures are silent: the resolver mirror, the control-kind tables, and labels re-derived from ids. A fourth catalogue, OSC's address table, lives on the desk. The target serves the answers instead.

One form, three hosts

  • A generic BindingForm renders any function from the catalogue. The inspector (A), the table's compound Binding cell (C) and the assign flow (D) all mount it.
  • A new function is then one Kotlin entry and no client code. The OSC address table is the precedent: the desk serves what each address does.
  • A golden fixture shared by Kotlin and TypeScript catches drift in the catalogue and map, as spreadShape.fixture.json does.

Fit on the sheet kit (C)

  • Fits: divider rows, a layer partition chip, dead-first sort, blank dependent cells, per-row options, fill in visible order (as the patch list's Address does), the phone forms.
  • Missing: a skip that depends on the value, accepts(row, value), since a fill over a fader and a button differs per row. Also an intersection of options over a mixed Does selection, and two-level grouping.
  • Live values stay out of the table's rows, which would otherwise re-render 20 times a second.

D's doors already exist: the stack list, cue actions, busk pads and pages, the Look sheet, the palette editor, the speed master sheet, and the fixture and group sheets, each about three lines on CopyOscAddressMenu's adapter. After the library goes, the Surfaces route no longer needs DeskDndProvider.

Migration and sync

What has to move, and what operators will notice

Stored rows

  • Database step 15, SurfaceGrammarMigration, on AttributeNamesMigration's pattern, backed up only when rows exist. One pure translate function is shared with LegacyNames for older archives, as consolidateFx is.
  • An encoder row holding a button target becomes the push part, read from the profile. Int-only cue and stack rows resolve to their uuid, or become Unknown and keep their bytes. Flash's raw max becomes a percentage. Strip rows carry across as they are; session 5 turns them into one job per device type, layer and region, with its own database step and formatVersion.
  • The table is rebuilt so its unique slot index includes the part, as step 14 rebuilt busk_pads. SQLite can't alter an index.

Sync and OSC

  • formatVersion 53 with minReader 53, the v39 precedent: an older reader would decode every binding as Unknown. Base snapshots taken before v53 are re-hashed, as PreV39BaseSyncTest does, or every untouched binding reads as a conflict.
  • A jobs folder needs its disposition, exporter, importer, coverage test, non-default fixture values and a frozen v52 archive.
  • OSC addresses don't change: they build targets in memory. /on, /off and /press map to On, Off and Toggle, and a number to a value taken whole. OscAddressesTest becomes an address → behaviour table, which is the proof QLab is unaffected.

What an operator will notice

  • A strip encoder's push no longer sends its attribute to full. The push is empty until bound.
  • A flash on a head whose range ends below 255 lands at a different level, because flash becomes a percentage.
  • A pan nudge now also holds tilt against later cues, because it writes position. That's what lets it beat a Circle.
Suggested order

Six sessions

Each is one PR across the wire where it touches both sides, as the repo's rules ask. The model and its migration go first, because every later session builds on it.

  1. The binding and its migration. Binding, Subject, How, parts, specs and one dispatch; Heads.of with elements and white-mix colour; records by uuid; position key; flash stored as a percentage; database step 15, the archive translate and formatVersion 53; OSC onto the new grammar; strip rows carried across as they are. Behaviour is otherwise unchanged but for the three changes listed under migration.

  2. Feedback. One entry, signals, the readback loop off the transmit thread with Local over the cue layer, one jump rule, LEDs on the functions including encoder pushes, holds keyed by control part, and live state per device if question 5 says so.

  3. Served map, catalogue and editors A and C. surfaceMap.state, /surface-functions, the slot upsert and identify mode; the inspector and the mapping table; the library, picker, matrix and overlay deleted.

  4. New functions. Clear, Blind, Release, Record and Update; Locate, Fan and FX speed on groups and fixtures; Flash and "follow the encoder page" on the selection.

  5. Jobs. Job regions in the profile, the jobs record and its sync folder, live derivation, strip rows turned into jobs with their own database step; editor B.

  6. Assign from the thing. Assign to surface… on the nine record kinds, the reverse index and Bound on everywhere.

Tests: in the backend about a dozen files are rewritten (serialisation, health, dispatch, strips, selection writes, router, publisher wiring), plus a migration test over a frozen database, a v52 archive test and a pre-v53 base-sync test. In the frontend about 110 tests go with the deleted files, and new ones cover the map reducer, the catalogue form, the inspector, the table, the assign flow and the shared golden fixture.

Agreed

Decisions the review raised

These came out of the code rather than the concepts. Chris's answers, 8 Nov 2026, all as recommended.

  1. "The stage" is the cue layer under Local, with no FX. Motors and pickup stop chasing a running FX; a GO still moves un-held faders as it fades.

  2. The readback looks beneath a held flash and ignores park. A flash doesn't slam every fader on its key to full, and a parked dimmer's fader shows what it would take over.

  3. Identify mode captures without firing. While the app waits for a touch (A or D), the next press is captured and not dispatched: one press, a banner, a 30 s timeout.

  4. The desk serves the map and the catalogue. The browser keeps no copies of the resolver, the kind tables or the label rules, and a golden fixture guards the wire.

  5. Bindings per device type, live state per device. Two identical surfaces share bindings, but each keeps its own layer, encoder page and held flashes.

  6. Record takes the Record sheet's defaults: the programmer's FX, held scenery and held tempos. Update with nothing included does nothing and says so.

  7. Fire stays fixture only.

  8. minReader 53 is accepted. An older desk refuses a newer show rather than losing its bindings.

Method: three read-only reviews (the binding model and write path, the feedback path, the frontend), each briefed with the agreed model. Every finding marked verified was checked in the code for this page; one reviewer claim didn't hold, that binding health goes stale in the view (store/surfaces.ts:77 subscribes), and is left out.
