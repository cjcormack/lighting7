The desk resolves, on both sides. The programmer's Spread sends the marquee's heads as targets — a group row to its visible members, an element row as {fixture, element.key} (the cells contract the desk already takes), a fixture row as itself — plus the family pill's mask, and POST /programmer/spread writes one literal per head into Local. fanValues and fanColours are deleted with it; the position exclusion goes too, because the objection was to a byte lerp and the desk lerps degrees.

The family is the marquee's, so the segment is answered and drawn checked — never hidden: the panel is one component, and a row that appears only in some hosts is how two hosts drift. A marquee spanning two families (Dimmer + Colour) draws the segment live with both offered, as the chooser Fan drew for the same case. The Property row appears wherever the family has more than one, exactly as the busk tab draws it.

The count moved off the top line and into the read-out: 4 heads · Local on the left, the marquee's family on the right — the busk tab has the band for this and draws neither; the popover has no band, so the read-out line the colour editor already carries takes it. No editor says Applying to N targets any more.

Live on the programmer too, off by default, through the same useLivePush; Apply always sends and reads Send again while Live is on. A cell editor writes as it goes already, so the two surfaces agree: a value judged by eye lands as the hand moves.

No Save as Look… in the programmer's footer (drawn without it; open call 1). Record is one row up and is how every programmer state is kept; the busk tab has no Record and so carries its own save. The footer is one component with a save slot the busk host fills.

Over: Cells is offered when a selected fixture has elements, with the count, as the busk tab draws it; disabled with the reason otherwise. This changes the programmer's default: Fan expanded a bar into its cells always, Spread treats a fixture row as one head unless the switch says otherwise — the busk default, said once (open call 5). An element row selected on its own is a cell by construction.

What the request carries from the programmer, and what comes back

Request — unchanged but for the flag

targetsthe marquee's heads: group rows expanded to their visible members, element rows as cells, fixture rows as themselves — templateTargetsFor's rule, so a press and a spread cannot name different heads familiesthe pair the press sends (usePressFamilies) — the desk's while following, the tab's when unlinked propertythe column's property, or the one the Property row chose from / to / curve / order / parts / over / seedas the busk tab sends them writenew: true (default, Local) or false — resolve and answer only, for a focused Look layer

Response

written[]{target, propertyName, value} — the literal the head got, in the Look row grammar, not the intent (a backend change: today intent.serialize()) skipped[]heads without the property, with the reason skippedFamiliestoasted in skippedRowsMessage's vocabulary, as the busk tab does

The programmer reads the response for skippedFamilies and, in layer scope, for written[]; it never draws a preview from it — the grid is the preview, as the rig is on the busk view.

The keyboard reaches both hosts. useCellEditorKeyboard wraps the panel: the first field is focused on open in the popover (not in either sheet), comma steps From → To, Enter applies — on the busk tab too, which had no keyboard convention. Escape is the surface's and closes the popover; the docked tab has no Escape, as the docked rail has none.

Row C's ⏎ edit · ⌫ clear hints stay; a third for Spread is not added — Spread is a verb with a panel, not a key.
