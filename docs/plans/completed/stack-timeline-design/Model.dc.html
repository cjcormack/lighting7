Columns, the run key, and one route for every write

The grid is derived: nothing stores a column. The client reads every cue's layers, effects and scenery for one stack, groups them into columns, and writes back through one stack route. The one model change is a run key on a cue's ad-hoc effects.

What a column is

KindColumn keyA filled cell isOn / off
LooklookId + one target, or none for the Look's own fixturesA cue_layers row for the Look whose targets include the target (or are empty)The press, on that target or on none; settings copied (D6)
PalettetemplateId + one targetA layer of the palette covering the target. One layer over Front and Back is two cells.The press: same-family palettes come off those heads (D5)
EffecteffectType + propertyName + targets as storedA cue_ad_hoc_effects row with that signature; cells sharing runUuid draw as one runOn copies the nearest cell's row, run key included; off deletes the row
SceneryelementUuidA cue_scenery row; between changes, the tracked stateSet writes the state and transition; clear deletes the row and tracking resumes

A Look's own effects stay inside its column: they already continue across the cues that layer it. A palette that holds an effect is a palette column like any other.

The run key

Q2 → Q3same key, same settingsAdopted: the running instance moves to Q3, id and phase kept, as a Look's effect is today.
Q3 → Q4same key, new speedAdopted, then edited in place through applyEffectUpdate, phase kept (D8). A move between Seconds and a master restarts the phase, as Update stage does.
Q6 → Q7different keysQ6's effect shrinks out over the fade and Q7's grows in from phase 0: today's behaviour, drawn ↺.

A paused or N-shot effect is never adopted (mayContinue), key or not.

Stored as cue_ad_hoc_effects.run_uuid, nullable, and runUuid on the cue's effect DTO and its sync record. Sync formatVersion 36 → 37; RichProjectFixture sets one so the round trip sees it.

Assigned when a cell is filled from a neighbour (On, drag, Fill ↓). Break run gives a cell and those below it a fresh key; Join run takes the key from above when the signature matches. Look effects keep today's rule.

{ entries: [{ entryId, cueId, layers: [{ id, source: {kind, id, name}, targets, sortOrder, enabled, amount, blendMode, propertyMask, stomp, timed, speedMasterUuid, rateSpeedMasterUuid }], effects: [{ id, uuid, runUuid, effectType, propertyName, targets, settings }], scenery: [{ elementUuid, state, transitionMs }], trackedScenery: [{ elementUuid, state, fromCueId }] }] }

Its own read keeps CueStackDetails light for the Cards and Table. Columns, runs and ranks are computed in one memo on the client.

Writing it

Every gesture is a batch of ops on one new route, POST /projects/{id}/cue-stacks/{sid}/timeline/edit {ops, dryRun?}.

GestureOp
A layer cell on or offlayerOn {cueId, source, target, settingsFrom?} runs LayerPress.press and then applies the copied settings, in one transaction; layerOff is the off press. Answers what it released, for the toast.
Drag, Fill ↓, a range On or OffOne op per cell, one request.
Replace across a rangereplace {cueIds, from, to, keepSettings}: the layer's source swapped in place where the cue lacks to; removed where it has it.
A layer's settingslayerSettings {cueId, layerId, fields}, the cue editor's layer fields.
An effect cell, a runeffectOn {cueId, fromEffectUuid}, effectOff, breakRun, joinRun.
A scenery cellscenerySet, sceneryClear, checked as PUT /cues/{cid}/scenery checks.

All or nothing, every problem named at once. It answers the cues it changed; a live one among them is marked edited since GO and nothing is sent (show-cue-editing D4). It fires cueListChanged and cueStackListChanged. The client keeps the inverse ops, so a gesture is one Undo (C3).

Size. A stack of 60 cues and 30 columns is 1,800 cells, which the sheet draws without virtualising. Measure at 150 × 40 on the iPad frame before deciding otherwise.

Tests. The sync bump runs the full suites locally. CueHolds gains run-key adoption tests beside the P4 ones; the route gets one test per op and one for a mixed batch rolling back.

MCP. No new tool. The ops are the route's; an AI tool for runs can follow once the route has settled.
