Stack Timeline

A third view of a cue stack, beside Cards and Table: one row per cue, one column per Look, palette, effect and scenery element, so whether a Look is in a cue is a cell you can see and change. What the code says

Lighting does not track. A cue is a complete state, and only scenery tracks. Lavender in Q2 to Q4 is three separate layers, and the grid makes three read and edit as one.

A GO carries an effect over only on its stored row's uuid and settings. A Look's effect continues across the cues that layer it; an effect copied into the next cue restarts from phase 0. Hence the run key.

The press already works on a stored cue, per target, sending nothing.

The stack list carries counts only, so the grid needs a read of its own.

Decided

Settled with Chris in the first four rounds of questions.

D1

Cues as rows

Cue, name, fade and follow at the left, the grid to the right, as on every desk's track sheet.

D2

A third mode of the stack view

Cards · Table · Timeline, keeping the Table's rows, row drag, edit lock and bottom pane.

D3

A column per record and target

A Look (its own fixtures, or one target), a palette on one target, an effect by type, property and targets, a scenery element.

D4

Cells stay per cue

Neighbouring cells draw as one bar; drag, fill and range on/off edit them. Layers do not start tracking.

D5

A palette cell follows the press rule

Other palettes of its family come off the same heads in that cue, and the grid shows it.

D6

Settings are copied, rank is shown

From the nearest cell above, else below, else the press defaults. A new layer goes on top.

D7

Effects get columns and a run key

Cells sharing a key are one run, and a GO hands the running effect on, phase kept.

D8

A change mid-run is an edit in place

At that GO the effect takes its new parameters with its phase kept, marked ◆.

D9

Scenery: a column per element

A change is a cell, a tracked state a line, both editable.

D10

Timing and live state

Fade and follow; the live cue framed with its fade running; the next cue; Edited since GO.

D11

In the first version

Selection and family filters, Replace across a range, a settings popover per cell, and a plain + Column.

Decided in a second round

Each as recommended.

Column order

First use, grouped by kind, reordered per window and never stored.

Declined: a stored order per stack.

The run key at a GO

Ad-hoc effect rows gain runUuid; sync goes from formatVersion 36 to 37. A paused or N-shot effect is never handed on.

Q2 → Q3

Same key, same settings. The running effect moves to Q3, id and phase kept.

Q3 → Q4

Same key, new speed. Handed on, then edited in place, phase kept ◆.

Q6 → Q7

Different keys. Q6's shrinks out over the fade and Q7's grows in from phase 0 ↺.

Reads and writes

Nothing stores a column. The client reads one stack's layers, effects and scenery from GET …/cue-stacks/{sid}/timeline and derives columns, runs and ranks.

Every gesture is a batch of ops on POST …/cue-stacks/{sid}/timeline/edit: layer on and off through the existing press, settings, replace, effect on, off, break and join, scenery set and clear. All or nothing; a live cue it touches is marked edited since GO and nothing reaches the stage.

The files in docs/plans/completed/stack-timeline-design/ in lighting7 are the authority; this page is a copy for reading. Act 1's first cues, the Looks, fixtures and scenery are the desk's; the other cue names, the palettes, effects and run keys are illustrative.
