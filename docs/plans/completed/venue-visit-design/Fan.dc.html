S12 · Fan: Spread’s relative mode

Spread gains a second mode on Position: Fan, an amount around each head’s own position, symmetric about the middle of the selection’s order. It is the same panel (components/editor/SpreadPanel.tsx) in the same four hosts, the same route (POST /programmer/spread, which grows a mode) and the same Curve · Order · Parts · Over rows. Only the endpoints change: From · To becomes one Amount per axis. The desk does the arithmetic, as it does for every intent, so the panel never computes a position. The board answers the plan’s six questions as nine calls, at the foot.

One row replaces From · To. The first row is the mode and the axes, Ends · Fan and Pan · Tilt · Both, which fits 288px on one line. Below it is one amount row per axis: a centred drag strip and a typed field. The read-out under them says where the heads started and offers Re-read. It also names the heads the fan pushed to the end of travel. Ends draws exactly as today.

The family segment and the label line are as today. The marquee answers Position and the panel opens one row down, in the mode it was last in. A colour or level marquee never shows the mode row.

Live is the fan gesture. Live on with a drag is fanning in and out by eye, the reason Spread has Live. With Live off, the strip and the field set the amount and Apply sends it. Send again resends against the same anchor, so the result does not change.

The skipped heads are Spread’s. A par in the marquee is skipped by name and takes no place in the order, as in Ends since editor-kit session 3.

The grey dashed line is each head’s own position (its base) and the amber line is the head after the fan. Under the heads are the offsets in centre steps, A × (2t − 1), with t from SpreadPlan.fractions unchanged. A head’s result is clamped to its travel and named in clamped.

4 · The wire
// POST /projects/{id}/programmer/spread — the same route, one mode more
{
  "targets": [{ "type": "group", "key": "movers" }],
  "families": ["POSITION"],
  "property": "position",
  "mode": "FAN",                 // absent: "ENDS", byte for byte today's request
  "fan": { "pan": 40, "tilt": -12 }, // centre steps; an absent axis is not fanned
  "base": [                     // absent on the first send: the desk reads each head
    { "target": { "type": "fixture", "key": "mover-1" }, "value": "142,98" }, …
  ],
  "curve": "LINE", "order": "LINEAR", "parts": 1, "over": "HEADS",
  "write": false                // the Look layer and the Values grid, as today
}
// 200
{
  "written": [{ "target": …, "propertyName": "position", "value": "102,110" }, …],
  "skipped": [{ "target": …, "reason": "does not pan and tilt" }],
  "base": [{ "target": …, "value": "142,98" }, …],  // where each head started: sent back next time
  "clamped": [{ "type": "fixture", "key": "mover-6" }]  // at the end of travel
}

The route grows the mode; nothing new is stored. mode: FAN replaces from and to with fan. Every other field keeps its meaning: the mask, the targets, member order for one group, the two passes that skip a head with no position, Over, and write: false. The answer’s written[].value is still the literal, so the Look-layer and Values-grid arms land it as they do today.

Defaulted fields, sent only when used. An Ends request is byte for byte today’s, and the panel omits mode, fan and base outside Fan. The reason is the one that keeps write absent when true: this Json refuses an unknown key, and a desk mid-upgrade would otherwise 400 every spread.

The encoder calls the same function. The route body and SelectionFan both go through one desk resolve, the encoder holding its own anchor. It writes owner surface, the panel owner WEB, as every other door does.

5 · The calls
#QuestionDrawnDeclined
1The nameEnds · Fan, a segment on the Position family's first row. Spread stays the verb, the panel and the button. The editor kit retired "Fan" as a second name for first→last, which is what Spread already did. This mode is something else: an offset around each head's own position, and "fan" is what other desks call that gesture. Ends names the mode Spread has today, the two endpoints."Absolute · Relative" (it says how, not what) · "Spread · Fan" (the mode is named like the panel)
2Pan, Tilt, BothA second segment, Pan · Tilt · Both, beside the mode. Both draws two amount rows, each with its own amount, so a wide pan fan and a shallow tilt fan are one gesture. Position is one property (pan,tilt), so the axis not fanned is written at its own base. The head's literal still names both.One amount for both axes (rarely what is wanted) · a 2-D pad (one finger cannot hold one axis still)
3The amountThe outer heads' offset, on S11's scale: −128…+127 centre steps, one step a coarse DMX unit. 0 is no fan. Negative crosses the fan. Drag: the strip is centred at 0; press anywhere and drag, ⇧ for ¼ speed, double-click to 0. With Live on every move is sent, as Spread's Live already is. Field: typed, clamped. Encoder: below.A percentage of travel (S11 made position steps) · degrees (a head without a range has none)
4The centreSymmetric about the middle of the order: head i of n moves A × (2t − 1), where t is the fraction Spread already computes. Under Line the middle head stays put; with an even count the two middle heads move ±A/(n−1). The order is rig order, or, when the selection is one group, that group's member order (S7), as a spread is today. Parts makes each part its own fan about its own middle. Order and Curve keep their meanings, drawn against the midline: Mirror is a V, Random a scatter within ±A. Over: Cells fans a bar's cells.Centre on the stage's centre line (needs placements; Aim's job) · a separate fan maths (two shape vocabularies)
5Where a head startsLocal, Row C, the rail and the busk tab: Local's own value for the head where it holds one, which is what Record would capture. Otherwise, what the desk is sending now, park included, read the way Set locate from current reads it. Local wins because a fade in flight, a position effect or Blind make the output a poor base. A focused Look layer and the Values grid: the row being edited. A head with no position in the row starts from the stage, and the read-out says how many did.Always the stage (loses a Blind or mid-fade value) · a head with no row starts at 0 (a fan from centre surprises)
6The anchorThe starting positions are read on the first send and held while the gesture lasts, so Live does not fan a fan. They are dropped when the selection changes, the panel closes, the mode leaves Fan, or Re-read is pressed. The amount then returns to 0. The desk answers each head's start (base) and the panel sends it back with every later request. The client does not compute positions; it only returns the desk's literals.The desk keeps the anchor by request id (state on the server for a stateless route) · an incremental fan (Live drops intermediate sends)
7The encoderA binding target, SelectionFan(axis) with axis Pan or Tilt, on any absolute encoder. It acts on the desk selection: CC 0…127 is −128…+126, 64 is 0, and the ring shows the amount. The desk holds the encoder's anchor. It drops it, and returns the ring to centre, when the selection changes or when anything else has moved a selected head's position since the fan last wrote it. The fan writes owner surface. It is not an encoder-bank property: the bank drives one head per strip, and a fan is one gesture over the whole selection.An encoder-bank entry (per strip, so eight fans) · a relative encoder mode (the surface code is absolute-only)
8Spread… in the footerAfter Aim…: Save as palette… · · Aim… · Spread…, the colour footer's order (Spread last). At the popup's 288px the two fold to their icons, their words on the title, and the save keeps its word: the colour footer's fold, since the three worded buttons need about 300px. It opens the rail's Spread tab on Position, in Fan, at 0, over the cell's heads. A colour's Spread… seeds From; a fan needs no seed, because it starts where the heads are. Drawn in the programmer only, like the footer. In Output it is refused with Output's words. In a focused Look layer it stays live and lands in the layer, where Aim… is refused.Open the popover at row C (two Spreads at once) · seed Ends with From = the cell (the gesture the cell already is)
9ScopeFan is on Position only, as the plan says. Level, Zoom and the rest keep Ends. No formatVersion: a fan writes literals and stores nothing.A relative mode for every percent property (not asked for)
