The parameters that are new to us

Spread, blocks, groups and wings shape where each head sits in the cycle; direction runs the cycle itself; size and fade scale what the cycle produces. The first four belong to the distribution, the last three to the running effect.

What we found in our code

  • The engine can already drive zoom. FxTargetFactory resolves any slider by name and checks only the output type, so Sine Wave on zoom works through REST, a cue or the AI. The picker never offers it: every slider built-in declares [dimmer, uv] and a new definition gets [dimmer].
  • A setting (colour wheel, gobo slot) takes raw bytes through SettingTarget, always overriding. There is no slot-aware output.
  • Spread is fixed at the whole cycle. LINEAR is index / size; EDGES_IN and SPLIT give the same offsets.
  • Direction is an order, not a run. REVERSE and PING_PONG reorder heads; reversing the waveform itself is up to each script.
  • Effects snap at GO (CueStackManager, CueCrossfadeDriver). intensityMultiplier exists and nothing sets it.
  • Effect rows store their fields as columns (look_effects, cue effects, a template's effect), so a new field on the instance is a formatVersion bump (27 today, more after S15 and S16); a new parameter of one effect is a key in parameters and is not.
  • S15 has not landed. This plan builds on it as agreed: an effect's timing is a speed master or seconds, and a new effect is one bar on its family's usage master.

And what the plan adds

  • Size is a weight applied after the blend: out = before + (blended − before) × w, with w = size × envelope × stack size. It replaces the raw-output scaling that once dropped an Override effect to 0.
  • A continuing effect is matched by its Look effect uuid and target, which survive a contents edit since 652128a; anything else leaves and arrives.
  • The desk owns every rule. The editor's dial preview is the one client copy, of the spread's shape, pinned to the desk's by a shared vector.
  • Three formatVersion bumps, one per session that stores a field (1, 2, 3); the step lists ride parameters. No stored effect changes meaning.

What changes on screen

The effect editor changes once, and that carries the new parameters to every host: the FX tray, the rail's popover, the add sheet, the effect-palette editor and the busk Effects tab, which all mount FxEffectFields. Size and Direction sit beside Speed; a Spread section holds the order, Spread %, Wings, Blocks and Groups over a row of phase dials; Runs (N-shot) joins Advanced.

The busk view's chrome does not change beyond a pad's detail line (Colour Cycle · 1 bar · M2 · ← · 60 %). The size fader is a cue stack's, so it lives on the stack in the Show view and on the busk Show tab's runner, and binds to a MIDI fader. The picker gains a Beam family.
