The Screens sheet: a window's setup from any window

The sheet behind the profile menu already addresses every window by its registry row — rename, view, full screen. It is the natural home for the per-window facts this proposal adds, under one test: can setting it from another screen lose something the operator at that window built? If not, it goes on the row.

On the row — nothing is lost by a remote set

Focus. Flipping Screen 2 to Pads from Screen 1 is the two-screen flow itself.
Sheet. Same reasoning, same command.
Page, for a busk row. A remote set unlinks that window onto the page, exactly as arriving with ?page= does; the chip on that window says so.

Not on the row — a remote set would decide for someone else

Selection follow. Unlinking snapshots what that window shows, a selection the sender cannot see. Shown as state, changed only on its own chip and ⌘K, as now.
The rig and the pad pages. Project documents edited in place under Edit layout; the sheet is about windows.
Rows in the split, edit mode. The handle's and the page's; too fine to drive from elsewhere.

The sheet must not learn the word “busk”. Each entry in lib/windowViews.ts gains an optional options descriptor, and a row renders whatever its current view contributes — today only Busk contributes anything. The write is one generic command, windows.viewOptions {targetId, view, options}, keyed and broadcast like windows.show; the named window applies it to its own tab facts and re-announces, so the sheet's rows come from the registry and never from a guess.

// lib/windowViews.ts { id:'busk', label:'Busk', segment:'/busk', options: [ { key:'focus', label:'Focus', kind:'enum', values:['split','pads','rig'] }, { key:'sheet', label:'Sheet', kind:'enum', values:['none','speed','colour','spread'] }, { key:'page', label:'Page', kind:'page' }, // resolved against the fetched page list ] } // the announce carries the current values, so a row can draw them: windows.announce { windowId, name, view, fullscreen, follows, viewOptions? }

One wire trap, already recorded. The desk's announce is deserialised with a bare Json — one extra key drops the whole frame silently. Adding viewOptions is a backend change first and a client change second, and windowsApi.test.ts's pinned key set moves with it.

This is where saved layouts start to earn their place. With view, focus, sheet, page and full screen on every row, a layout is one row per window of exactly those five facts. The deferred FU-SCREENS-LAYOUTS stays deferred, but the Layouts… button is drawn here so the sheet is laid out for it, and its record is the announce's shape rather than a new one.
