Selection surface. Every serious desk has moved from a list to a built surface — MA layout views, Eos magic sheets, Hog plots, MagicQ execute regions. All four separate the surface from the library and let the operator arrange it. None of them fan out a group into a strip the way lighting7's band does today. Hence: the rig as a document (Rig board), rows first, plot as a rendering.

Layout and screens. Titan's workspaces, MA's views, Eos's snapshots are all per screen, recalled by a button. lighting7 already has the windows registry and per-tab flags; focus is the missing one, and FU-SCREENS-LAYOUTS is the saved-arrangement half, which this proposal leaves where it is. Fan curves are Titan's vocabulary, because it is a set of pictures.

Sub-fixtures. Two camps again: a mode (MagicQ's element mask) or a property of the selection (Eos's .n, MA's MAtricks, Hog's buddying). The busk view is a touch surface with no command line, so the choice is made for it: on the tile, in the selection, never a mode. What none of them draw — and lighting7 can — is the cells' live colour on the tile itself, since every stage read already goes through one colour dispatch.
