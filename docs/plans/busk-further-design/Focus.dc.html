Per-window facts, all in lib/buskWindow.ts on deskFollow.ts's model

busk.focussplit · pads · rig (default split) busk.rigRowsrows shown in split, 1…N; clamped to the rig's row count busk.sheetspeed · colour · spread (default speed) busk.sheetOpentrue · false (default true at ≥ md)

Arrival params ?focus= ?sheet= are latched once per tab exactly as ?page= is, and mirrored back with replace. A reload is never an arrival.

Ways to change it

The Focus segmented control on the page strip; the band handle; the sheet's fold chevron and tabs. ⌘K: Focus pads / Focus rig / Split and Show <view> on <window> gains a focus arm, built by buildWindowCommands. Screens sheet: a focus picker beside the view picker for busk rows, so “make Screen 2 the pads” is one click from Screen 1. MIDI: BuskFocusSet / BuskSheetToggle as window-addressed commands (windows.focus), the same shape as windows.show.

What focus must not do. It never hides a state the operator could be surprised by: a lit pad in Pads focus still shows the selection it will press onto (the strip); a rig in Rig focus still names the page a MIDI press would reach (the strip). And it is not a second edit mode — Edit layout forces Split for its duration and restores the window's focus on Done, because a palette drag needs both regions on screen.
