Save as template…Pick

The Colour tab is a busking gesture, so it writes literals. Every drag sends programmer.setColour per selected target — a group as a group write, a cell by its element key — exactly what a template pad's click does, and what the programmer's colour cell does. It is not a layer and has no ⌥ arm: a picked colour has no referent for a layer to follow. Save as template… is the route to something trackable, through the same POST /templates/from-programmer the strip uses.

Reuses ColourPickerPopover's content — the react-colorful picker, the typed R/G/B, the emitter rows — hosted in a rail rather than a popover. The emitter rows show for the selection's union (targetEmitters), with the count of heads that take them; a head with no white simply drops its byte, as a colour cell commit already does. compact under 750px of height, the same fold the cell editor has.

Recent is the template recents row (lib/templateRecents.ts, colour family only): a tap is a template apply, so it stamps lastPressedAt and lands as literals like the chip. No new list, no new order.

Pick reads the selection's current colour off the stage source (the same fixtureAppearance dispatch the mini-stage draws with) into the picker without writing — the eyedropper a busking operator wants when a look is nearly right. Where the selection disagrees, the first head in rig order wins and the field says mixed.

The mask. The desk's family mask gates presses, not value writes; a colour drag is a value write like a cell edit. So the sheet does not refuse under a Position marquee — but the tab's header says what it is about to do (Colour of 14 heads) and reads the family pill, which is the honest answer the programmer's Set gives.

Fold state and tab are the window's (busk.sheet, busk.sheetOpen), never the desk's. Below md the rail is not drawn, as today; the Colour and Spread tabs are then reached from the narrow target sheet's footer.
