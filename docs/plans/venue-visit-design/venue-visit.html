What the code showed

Three surveys of the code on 2026-10-14 decided which notes are bugs, which are small, and which change a model.

  • Every cue belongs to exactly one stackcues.cue_stack_id is non-null and numbers are unique per stack. The card's Remove hard-deletes the cue, and deleting a stack deletes its cues. Shared cues are a model change, so R1 designs it first.
  • The show position lives only in the URLThe view switcher links to bare /show, so a round trip to the programmer drops the stack and ?cue=. "Edit in Programmer" is Include and never leaves the page.
  • Group order already existsfixture_group_members.sort_order drives distribution and spread, but only the Patch list's group sheet can reorder it.
  • Locate is per category, not per unitPan and tilt go to mid-range for every head. Nothing records where this particular unit should point.
  • Lamp commands exist, one unit at a timeOnly the Robe ColorSpot and the MAC 250 declare lamp on/off, and only per patch. There's no bulk run and no command role to ask for "every lamp off".
  • The grand master is a switch with no UIGlobalScalerState is on/off. The Show bar's DBO tile does nothing (FU-FE-DBO-INERT).
  • Effects start at one beat a cycleThe picker starts every effect at beatDivision: 1 on master 1, one cycle per beat. Only wall-clock effects can run in seconds.
  • Seven ways to apply to a selectionThe palette strip, the picker, busk pads, the add-layer sheet, the FX sheet, the busk side sheets and Include. Only the colour cell offers palettes from its popup.

Four mechanisms, drawn out

S1 · landed in 4a1a8fb4

A palette on a fixture whose colour lives on its cells

In its 24-channel mode the Shehds keeps pan, tilt, dimmer and strobe on the parent and colour on three zones. A palette applied to the parent found no colour there and skipped it, writing nothing. The frontend made it worse by turning a selection of zones back into the parent. The fix fans a parent target out to the elements that carry the property, in the click, the cook, Spread over Heads and busk presses.

S3 · decision D11 · landed in e2153f5c

Renumbering a cue to move it

Before S3 the backend derived every auto number from the nearest explicit one. Auto cues before it counted up to it, so the stack was always in order, the out-of-order banner never appeared, and the cue never moved. Under D11 a renumber leaves its auto neighbours alone, so the banner appears and Fix Order moves the cue.

S11 · decisions D3, P3

Position as a fraction of travel

Position is read and typed as centre-relative DMX: 0 is the centre of travel (DMX 128), and the ends are −128 and +127, since the scale is exactly DMX − 128, whatever the head's angle range. The fine channel still rides underneath. A generic position palette therefore means the same fraction of travel on every head rather than the same angle. Old palettes stored in degrees keep resolving as angles, because there are no migrations; one is saved in the new form only when someone edits it.

S6 · decisions D9, D13, D14, D18, D19

Making the rig safe, undoing it, and quitting

Making the rig safe and quitting are separate actions, because the rig should be safe before the app exits. The desk keeps running once the rig is safe, and says so on every window.

RunningShow output, lamps struck.
→
Make rig safeLamp off every unit with a lamp, or the selection's. Wait out each command's hold, then black out.
→
Ready to switch offShown on every window for as long as it's true.
→
Quit deskAdmin only, on the desk's own listener. Confirm, with a warning if the rig isn't safe. The Windows launcher exits too.
Undo strikes the lamps that Make rig safe turned off, then releases the blackout. The desk remembers which ones until it quits.
Staggered strikes: one unit every couple of seconds, to spread the inrush current, whether from Undo or a selection.
Too soon to restrike: a discharge lamp that went off recently is listed with its time left and struck when that time is up. Each lamped type declares its restrike time.
Clears itself: any GO, programmer change, lamp-on or leaving blackout ends "Ready to switch off".

Decisions

Agreed with Chris over four rounds of questions on 2026-10-14. D is a product decision; P is how the plan is run.

Cues and the cue list

D1One shared cue. A stack is an ordered list of cues, a cue may be in no stack, and only an explicit delete deletes one.
D11A renumbered cue shows out of order; Fix Order moves it. Auto neighbours keep their numbers.
D15A cue sets its speed masters whenever it becomes live: GO, GO TO or GO BACK. A tap afterwards wins. It doesn't track.
D20With shared cues, every GO into one of a cue's entries sets its tempo, even when another stack already holds the cue. Its events still fire only on the first hold.

Programmer and palettes

D2Templates become palettes in UI, REST, WS, MCP and docs. Tables, the sync folder and tmpl: refs keep the old name, so there's no format bump.
D3Position is centre-relative DMX around the centre of travel (S11 landed it as exactly DMX − 128, −128…+127), everywhere an operator types or reads it, palettes included.
D6Locate is stored on the patch, in its Focus facet, so a show can override a venue's.
D17A unit's locate is pan and tilt only. Everything else keeps its category default.

Output and the rig

D5The grand master is a continuous 0–100 % fader in the app bar, replacing the inert DBO tile.
D12On a head with no dimmer, the grand master scales the colour channels instead.
D8The blinder takes Colour as a warm/cold white mix per cell. Its two sliders stay.
D9Make rig safe and Quit desk are separate. The app keeps running once the rig is safe.
D13Quit desk is admin-only and never remote.
D14"Ready to switch off" clears as soon as anything sends output.
D18Make rig safe can be undone: lamps back on, then the blackout released.
D19A bulk lamp-on is staggered, with a restrike warning and countdown.

Effects, chrome and pace

D7An effect can run on its own cycle time in seconds, with no speed master.
D16A new effect defaults to one bar, on its family's usage master if one is tagged.
D4One sidebar state across all views. Immersive (⌘K) stays.
D10No hard date. The order follows dependencies and what got in the way on the night.

How the plan runs

P1One PR per session, on a claude/vv-<id> branch that claims it. Before the PR: main merged in, both suites green, docs and CLAUDE.md, follow-ups, an operator check, hand-offs to other plans, and a second commit marking it done in its own plan.
P2Rename before building: S4 lands before sessions that add UI copy.
P3Old degree-based position palettes keep resolving. New writes are centre-relative.
P4A design session holds back only what it might reshape.
P5No plan names a format version; merge order assigns it. A session writes the next number free and says sync vN in its PR title; if another PR with that number merges first, it renumbers in its merge of main.
P6Lanes across all seven plans, run in parallel. A session's body and its done-marker stay in its own plan, and the lanes carry no status.
