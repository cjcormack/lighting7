One layout, two pages. The reorder route already takes the whole layout, so it grows one entry kind (lookId) and the Looks page gets the drag handles and New group the Templates page has. A group shows on both pages; each page draws the members of its own kind and names the others in a footer row, so nothing is ever hidden.

Looks lose their client-supplied sort order. Today a Look's position is a raw number in the PUT body with no renumbering; with the shared layout it becomes server-owned and dense, the way templates already are. A Look joins a group from its editor's Group picker or by dragging here — the same groupId + groupIdPresent pair the template input uses.

The group header says where it will draw. Key colours is one family, so it stays in the Colour column; Movement holds Looks, so it carries a Looks pool badge. That badge is the derived home made visible — the one thing about a group an operator cannot otherwise predict from the list.
