Programmer fixes

Four things that get in the way on the programmer, reported together: you can't build a selection from cells that aren't next to each other, element rows open themselves whenever you come back, the value pop-ups don't remember what you just used, and a colour FX's picker sometimes closes in the middle of a drag. This page covers what the code does now, the change for each, and the five sessions that ship them.

1 · Non-contiguous cells 2 · Element rows 3 · Recent values 4 · FX picker closing Decisions Sessions

1Select cells that aren't next to each other

Now

A click on a cell always replaces the selection. Every cell button already passes its click event up, but the two tables drop it (onBeginEdit={() => onBeginCellEdit(row, col)}), and the hosts' handlers then call selectCells([cell], 'replace'). A ⌘-drag can add a block, because the marquee reads the modifiers, but there is no way to add or remove one cell. Only the cue Timeline handles a ⇧-click, with its own rectangle, and a click on its one selected cell toggles that cell's layer.

FixturesTable.tsx:1153 · SheetTable.tsx:930 · FixturesListContainer.tsx:660 · useSheet.ts:484 · CueValuesGrid.tsx:333
Change

A cell click takes the same modifiers as a row click (listSelectionIntentFor): ⌘/Ctrl-click adds or removes that one cell, ⇧-click selects the rectangle from the anchor to the cell clicked, and ⌘⇧-click adds that rectangle. A click sets the keyboard cursor, so the arrows and ⇧-arrows carry on from it. On a touch screen an Add latch on the selection bar turns a tap into a toggle.

One door per host: the kit's useSheet (every kit sheet), the fixtures container (Programmer · Fixtures · Groups), the cue editor's Values grid, and the Timeline's own click handler, whose ⌘-click never reaches its layer toggle

What a selection with gaps does

  • Writes stay per cell. The write path already groups the selection by column (cellsByColumn) and plans each column over its own heads. Set, typed values, ⌫ and Spread reach exactly the cells selected. Spread runs over a column's selected heads in row order and skips the gaps.
  • The desk's selection is still heads × families. The programmer publishes the cells' rows and the union of their families, which is the rule a ⌘-union of two rectangles already follows (useDeskSelectionBridge). So a palette press after the selection above reaches Wash 1, Wash 3 and Spot 1 in both Colour and Position. That is wider than the cells, and it is today's behaviour. Grid writes stay exact.
  • Rows and cells stay exclusive. A ⌘-click on a cell while rows are selected clears the rows, as a cell click does now. ⌘-click and ⇧-click on a row's name already toggle and range rows on every host.
  • The Add latch is drawn only where the primary pointer is coarse (the tablet). While it is on, a tap toggles a cell (or a row from its name) and a held drag adds a block. It drops when the selection clears or on Esc.

2Element rows stay as you left them

Now

Which groups and fixtures are open is useState in the container, so it is lost whenever the programmer unmounts. Coming back, the grid replays the last Include or "select these heads" request: the request lives in a module-level store that never marks a request spent, and the guard against repeats is a ref that starts again at 0 on every mount. The replay opens every parent fixture and group again. It also re-selects those heads, clears the filter, turns Lit off and scrolls.

FixturesListContainer.tsx:326 · :1240–1299 · store/includeSelection.ts:35 · programmerSelectRequest.ts
Change

Expansion becomes a per-window store, one per list and project, kept across navigation and reloads. An Include or select request lands once, then is spent. A toolbar button (after Lit on the plain lists, beside Groups on the programmer's row B) expands or collapses every group and multi-head fixture in the list, and ⌥-click on a chevron does the same.

lib/listExpansion.ts (createSyncStore, sessionStorage) · includeSelection's consume
  • Per window, per list: sessionStorage keys for Programmer, Fixtures and Groups, each per project so one show's groups never open another's. Each screen keeps its own layout, as the cue pane's toggle does. A key whose fixture or group has gone is ignored, and dropped on the next write.
  • Gestures that select elements still open their rows: Include onto an element, the heads chip's Odd/Even, Select by colour. They add to the stored set, so what they opened stays open. Only the stale replay goes.
  • A request is spent once landed. It is applied by the grid mounted when it was published, or, if none was, by the next grid of the same project to mount within five seconds; otherwise it is spent unlanded, so it never replays later or in another show. Spent is recorded in the store, not in a component ref, and React StrictMode's immediate remount still lands it, because the consume runs a task later and the cleanup cancels it.
  • Collapse all keeps the selection on screen. A fixture whose element rows hold the selection stays open, and so does a group whose member rows do, so a collapse never quietly empties the selection. A chevron click on that one fixture still closes it, as now.
  • The cue editor's Values view gets the same button. It keeps its own rule that a fixture opens when the cue holds one of its elements, and nothing is stored there.

3Recent values in every value pop-up

Now

Nothing keeps recent values. The only recency is a palette's lastPressedAt, which puts pressed palettes first in the Palettes band. There are three colour pickers: the kit's ColourEditor (the programmer, cue Values, fixture sheet, busk Colour, Fan), the FX editor's ColourEditorBody, and the palette editor's ColourControl.

lib/paletteRecents.ts · editor/ColourEditor.tsx · fx/ColourEditorBody.tsx · templates/familyControls/ColourControl.tsx
Change

The desk keeps a short list of recent values per kind and streams it to every window, so the tablet, the phone and both desk screens share it. One kit band, RecentValues, draws a row of them under the editor, and a tap sets that value as if it had been typed. All three colour pickers, the level and position editors and warmth mount it.

state/RecentValues.kt · recentValues.state / .record · editor/RecentValues.tsx

What counts as recent

  • A gesture's end, not a frame. A drag's release, Enter in a field, a recent's tap, a typed hex. The live pushes during a drag record nothing, so dragging across the pad adds one colour, not forty. A position over heads whose other axis differs records nothing, since replaying the pair would flatten them.
  • Not palette presses. They already have recency (the Palettes band, pressed first). A palette applied as values, and the colour Pick reads, are not recorded either: the row is for values you chose yourself.
  • Settings are left out. A setting's options (gobo slots, macros) belong to each model, so a recent slot name means nothing on another head. The setting editor is a type-ahead list already.
  • Twelve per list, newest first, no repeats. A value already in the list moves to the front. The row shows as many as fit, at most eight.
  • A tap replays a recent as if it were typed, through the editor's own typed path: the programmer's colour literal (#e0337a, with a ;w / ;a / ;uv byte for every emitter the editor holds, zero included), a level as pct:62 (the percent the grid reads for the byte committed, replayed as a typed percent), pos:-20,12 centre-relative for a position, and for warmth the kelvin and level the editor worked its colour out from. In the palette editor a colour recent is its hex alone, since a palette holds white, amber and UV as rows of their own.
  • Runtime only, per project. The desk holds the lists in memory, one per project. Switching shows keeps each show's list while the desk runs, and a restart clears them. Nothing is synced, so no sync formatVersion change and no table.

4The colour FX picker closes mid-drag

Reported on the programmer's row C FX button, a colour FX, dragging the colour picker's dot. Neither a real-Chrome harness nor jsdom reproduced it: a nested Radix popover counts as inside its parent, and a drag's release can't click Done. The cause is not known. The first draft of this page blamed the Lit filter hiding a head whose colour reached 0. Review found Lit reads dimmer channels only, so a colour drag can't do that. What the code does show is below. read, not reproduced

1 · the picker follows the selectionRow C's actions render only while the selection's visible rows are non-empty, and the FX button closes its picker when its offer turns disabled. While the window follows the desk, that offer reads the desk's selection, so another window or a surface emptying it closes the picker too.
2 · Lit can empty themLit keeps only fixtures whose dimmer is up. A dimmer wave or fade through 0 on a selected fixture takes its row away, and row C and the picker go with it. That is a real close, but not the reported gesture.
3 · the list picker floodsColour Cycle's list sends every colour move as a release, skipping the 50 ms floor: an updateFx, an fxChanged and a refetch per mousemove.
4 · and can reset its swatchAny value but the one it last emitted re-mints the swatches and closes the open swatch's popover. Here the value is the editor's own draft, which a desk echo never rewrites, so this fires only on a revert, a type swap, a reset, or an emptied list falling back to its default. It is guarded anyway.
Where

One colour (FxColourPicker) sends no release at all. ColourEditor's own picker already releases through window listeners (holdPicker), so a drag let go outside it still lands.

FxFields.tsx:1772, :1812 · FxColourListPicker.tsx:72 · ProgrammerAddFxButton.tsx:20 · ProgrammerAddFx.tsx:99 · FixturesListContainer.tsx:1606 · useLitFixtureKeys.ts · ColourEditor.tsx:418
Change
  • Lit holds still while something is open: an editor, the FX picker or a marquee. A dimmer fade can't take a row away under them, and no row moves under the pointer mid-gesture. The close rule itself stays: a filter you type that hides every selected row still disarms row C.
  • Both FX colour pickers release once, through window listeners like ColourEditor's, and drag live through the 50 ms floor.
  • The list picker keeps an open swatch while it is edited or a drag is live, and resyncs when it closes.
  • An opt-in close trace: with a localStorage flag set (no reload needed), the desk's own bundle logs one warning per close naming the door, including a desk-selection change and who made it. Off by default.

The plan's operator check repeats your gesture at the desk with the trace on, Lit on and Lit off. If it still closes, the warning names the door, and the plan takes a follow-up.

Calls this page makes, open to change

  • ⌘-drag keeps adding even when it starts on a selected cell. There is no subtracting drag, as in a spreadsheet.
  • Recents are runtime only. A machine-local table that survives a restart is a small later step if wanted.
  • Collapse all leaves open what holds the selection: a fixture whose elements do, a group whose members do.
  • The Add latch is not drawn for a mouse, which has ⌘.

Five sessions

One PR each, run by /next-session in this order. The bug fix ships first because it's small and the most disruptive. Recents are split so the wire change and its first host land together, and the other hosts follow.

Out of scope

  • A per-cell desk selection (heads with their own families). The desk keeps heads × families.
  • Recent settings (gobo slots, macros), recents that survive a restart, and clearing a recent by hand.
  • Making the three colour pickers into one. Session 5 mounts the same band in all three.
  • Expansion on the Cards and Stage views, which have no element rows.
