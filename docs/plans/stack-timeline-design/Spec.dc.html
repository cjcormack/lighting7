A stack's timeline: which Looks, palettes, effects and scenery each cue applies

The brief: "a timeline view for a stack, to see and edit when looks, etc. are applied to stacks and not. It should be in a table view so that whether a look is applied or not to a cue can easily be changed." Today the Table shows a count of layers per cue and the cue editor shows one cue at a time, so a question like where does Lavender come off? means opening cue after cue. Drawn dark and 1440 wide, like the earlier records; phone and tablet are out of scope (C6).

What the code says

Lighting does not track. Each cue is a complete state; a GO is built from the incoming cue alone. Only scenery tracks (SceneryResolver). So Lavender in Q2 to Q4 is three separate layers, and the grid has to make three read and edit as one.

A GO carries an effect only on its stored row's uuid and settings (CueHolds.continues). A Look's effect continues across the cues that layer it. An ad-hoc effect copied into the next cue is another row with another uuid, so it fades out and grows back from phase 0.

The press already works on a stored cue. POST /cues/{cid}/layers/press applies the programmer's per-target widen, narrow and replace to a cue's layers, and sends nothing.

The stack list carries counts only: layerCount and adHocEffectCount per cue. The grid needs a read of its own. components/sheet/ already gives typed keys, the marquee and row drag, and CueSheet uses it.
