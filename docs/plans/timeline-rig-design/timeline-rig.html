Fixtures in the Timeline

The Timeline answers which cues is Lavender in? It cannot answer what is Spot 2 doing in Q5? This proposal adds rig columns: one cell per fixture or group per cue, showing the state the cue lands it in. A cell can be copied, pasted, dragged to the next or previous cue, and edited. It also gives the existing cells copy and paste, keeps Edit in programmer on this window when another window already shows the programmer, and lists what a review of the tab found.

  • One cell per target. The swatch is the colour with the level as its fill, then the level, then marks for position, beam and FX. The header names the fixture and its type.
  • A solid cell is the cue's own. The cue holds rows for exactly this fixture or group. An outlined cell gets its state from a Look, a palette or the fixture's group, so editing the cell would be the first row of its own.
  • Equal neighbours join. Cells whose state is the same as the cue above draw as one bar, and ◆ marks each change, so a column reads as a track sheet even though nothing tracks.
  • A group is one column. Uniform members read as a fixture does. Mixed members draw a striped swatch and a level range. A multi-head fixture opens into a narrow cell per head.
  • Columns come from you. + Column searches fixtures and groups as well as Looks and palettes, and + Selection adds the desk selection's targets. They are stored on the stack and synced, in the order you put them, so every window and every desk shows the same rig columns.
  • The desk resolves every cell. The same cook a GO runs, per cue, answered for just the columns shown. The browser draws it and works none of it out.

Part 2 · the rule

What a paste writes

A fixture's state in a cue can come from four places: its own rows, its group's rows, a Look and FX. A paste makes the destination land the same state by writing the fewest own rows that do it. An own row for a fixture beats its group's rows and every layer in the same cue, so those rows always win.

In the source cueThe destination getsWhy
A literal valueAn own row with that value, unless the destination already lands itTwo cues layering the same Look paste to nothing, and the Look stays the source of truth.
A palette referenceAn own row holding the same pal: referenceEditing the palette still moves both cues.
A value from a Look or the groupThe literal each head resolves to, as an own row, where it differsA Look lands whole, so one fixture's share of it can only travel as values.
DarkDark as own rows, if the destination would light it: dimmer 0 where the head or its parent has a dimmer, else its colour mix at blackDark is a state a paste must be able to carry.
Nothing for a family the destination setsThe destination's own rows for it are removed; a value still arriving from a Look or group stays, and the toast names itThere is no stored no value, and under a dark head it does not matter.
An FX on exactly this targetA copy. On the same target it joins the source's run where the cues are neighbours; on another fixture or group it takes a fresh keyThe Timeline's existing fxOn. Two FX of one cue cannot share a key.
An FX over its group or a selectionNot copied; the toast says soOne head cannot be cut out of a group FX without changing its spread.
  • Where it can go. The same column in any cue, of this stack or another. Another fixture of the same fixture type. Another group whose members are the same types in the same order. Anything else is refused by name.
  • Dragging. A rig cell carries a handle on its top and bottom edge. Dragging down pastes into each cue crossed, dragging up into each earlier cue, with ghost cells first. Fill ↓ and ⌘D do the same over a range.
  • The family segment is the paste mask. On Colour, a paste carries colour only, and the cells draw colour only.
  • One request, one Undo, as every Timeline gesture is. Nothing reaches the stage; a live cue is marked Edited since GO.

Part 3

Copy and paste for the cells there already are

The clipboard holds which cells were copied, not their values. A paste asks the desk to copy from those cues as they stand. It is shared by every window of the desk on this machine, so a copy on one screen pastes on another, and in another stack.

CopiedPasted intoDoes
Look or palette cellThe same column, another cueTurns it on with the copied layer's settings. The press rule still applies.
Another column of the same kindPaste settings: amount, blend, mask, stomp and timing onto that layer, turning it on first if it is off.
FX cellThe same columnA copy of the row. It joins the run where the cues are neighbours, else it takes a fresh key.
The same FX on another targetThe FX on that target with the copied settings and a fresh key, where the target has the attribute.
Scenery cellThe same element, or one of the same kindThe state and its transition.
A block of cellsA cell in another cueEach column's cells land the same number of rows down from that cue. Markers are skipped.

⌘X is a move. The cut cells stay in place, drawn dashed as copied cells are, and the paste turns them off in the same request, so one Undo takes both back. Esc or a new copy cancels the cut. A paste that would change nothing is disabled, and one the desk refuses names every cell it refused.

Answered 28 Nov 2026

Seven questions

  1. What does a pasted state write?

    The fewest own rows that land the same state, keeping palette references. Or always literal values for every attribute. Or the source's own rows only, ignoring what its Looks and group give it.

    agreed Fewest rows, references kept.

  2. Does a state carry FX?

    Only FX on exactly that target. Or also a per-head copy of group FX, losing the spread. Or never.

    agreed Exact-target FX only, the rest named in the toast.

  3. Where do rig columns live?

    In the window, like column order. Or following the desk selection live. Or stored on the stack and synced.

    answered Stored on the stack and synced, not the recommendation. + Selection stays as the quick way to add them.

  4. How is a cell edited?

    A popover with the programmer's controls, plus the pane and Edit in programmer. Or the pane only.

    agreed The popover, with both ways out.

  5. When a programmer is open elsewhere, what does the press do here?

    Stay, with a toast offering Open here. Or stay silently. Or a per-window setting.

    agreed Stay, with the toast.

  6. Should the Timeline's Undo become the desk's?

    One history and a working redo, against a slightly slower ⌘Z that restores through the journal.

    agreed Yes.

  7. Which review items come in?

    The seven marked in, or a subset.

    agreed All seven.

The plan

Five sessions

Session 1 · client

Edit in programmer stays put

Part 1: the rule in CueActions and the FX editor's door, the toast, and the Included heads written to the desk selection.

Session 2 · both

Rig columns, read-only

The stored columns and their sync, the desk's read of each cue's state per column, the cells, heads, joins and ◆, + Column and + Selection, the family segment on rig cells.

Session 3 · both

Copying a state

The copy op and its rule, the clipboard, paste, the two handles, Fill ↓, the refusals and the toast.

Session 4 · both

Editing a state, and copy for every cell

The popover and its value op, Clear own rows, the pane's Values tab on a rig cell, and Part 3's copy and paste for Look, palette, FX and scenery cells.

Session 5 · both

The review items and one Undo

The context menu, the top handle, the pickers, the header menu and drag, densities, Changes only, and the Timeline's Undo becoming the desk's, each edit its own History entry.
